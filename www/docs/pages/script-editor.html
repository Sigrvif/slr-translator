Script Editor

The Script Editor is the built-in JavaScript editing window, used wherever SLR Translator needs a small piece of custom code from you. In practice it edits project hooks — snippets stored inside a project and executed by the application at defined moments. The same editor window, extended with run and file toolbars, also powers the Automation Editor.

Opening it

The hook editor is reached from the project properties: open More Tools → Project Properties, open the Advanced tab, and under Hooks press Edit function next to On after export.

Editing

  • The editor is an Ace instance with JavaScript syntax checking and live autocompletion; script output and errors go to the developer console (the bug button opens DevTools on SDK builds).
  • The line above and below the editor show that your code becomes the body of an async function called with a this object. Clicking the highlighted this under the editor opens a reference popup listing the properties available on it; entries can be clicked to insert them at the cursor.
  • Ctrl+mouse wheel changes the font size; F11 toggles maximized window state; Ctrl+S saves.
  • If the editor is opened without a save handler it switches to read-only mode and hides the file toolbar.
The legacy F1 help entry of the old editor no longer exists; a help button only appears when the caller provides a help page, and project hooks do not.

Saving and persistence

Save does not write a file — it hands the code back to the caller, which stores it inside the project (options.hooks.afterExport). The hook is therefore saved and reloaded together with the project file. There is no Run button here: hook scripts are executed by the application, not on demand from the editor.

The “On after export” hook

  • Runs automatically after this project has been exported successfully — regardless of whether the export went to a folder, a zip, or through an engine's own export routine.
  • Before anything happens, a warning dialog asks for confirmation: the script is user code that is not part of SLR Translator, and it runs with the full access of the application. Canceling skips the hook for that export.
  • The code runs as the body of an async function: this is the global project object (the same one exposed to automations), and the first argument is the export options object of the run that just finished.
  • All application APIs are in scope — the project and its files, the UI layer, common helpers and Node's require. A typical use is post-processing the exported patch, but nothing stops a hook from doing anything else.
Because hook scripts are plain JavaScript with full access, only keep hooks in a project that you wrote yourself or fully trust — the confirmation dialog is the last line of defense.
