FAQ & Tips

Short answers to common questions, each with a link to the page that covers the topic in depth. The documentation ships inside the application — press F1 in the main window to open it at any time.

Getting started

Where do I start?

Create a new project, point it at the game executable, wait for parsing, then generate a glossary and run the full Batch Translation, reviewing flagged rows afterwards. The whole walkthrough, including wrapping and exporting the translation, is on Your First Translation Project.

Which translation engine should I use?

A local Sugoi server or a local DSLR endpoint (LM Studio, KoboldCPP, Ollama) keeps everything offline; online OpenAI-compatible APIs work too but send text out of your machine. The trade-offs and setup steps are in Translator Setup and Options Overview.

Always create a backup of the game before patching it

Exporting a translation produces translated data files meant to replace the originals in your game copy — keep a pristine backup before you copy them in, and let SLR Translator back up your project file on every save (enabled by default in General Settings). See also the warning in Your First Translation Project.

Editing and the grid

Why is only one of my translations used per row?

By design: on export and apply, the rightmost non-empty cell of a row wins. The columns form a workflow — machine translation first, corrections to its right — so a correction always overrides the generated text without deleting it. Details in Editor Basics.

A dialog says problematic cells were found — what now?

Open Find (Ctrl+F) and search for the text SHISAYE. Every hit is a row whose translation lost or broke something the game needs (control codes, placeholders, quotes). The Error Codes page lists every code with its cause and fix.

What do the colored strips on the rows mean?

They are tags that record how safe a row is to translate and what the tools did with it — the batch translator and export filters read them. The full legend is in Cell Color Tags.

Games and engines

The translated game shows boxes or garbled text, or crashes on startup

Two usual suspects: your system locale when playing the translated game (parsing and translation themselves are locale-safe — see Japanese Locale Configuration), and fonts: English text needs more room than Japanese at the same size, so menus overflow or break. The font steps per engine are in RPG Maker MV and RPG Maker MZ.

Why does my translated text overflow the message window?

Japanese windows fit far more Japanese characters than English words at the same width. Run Automatic Word Wrapping after translating so lines are re-broken to fit, and consider a more condensed font for the game (see the font sections of RPG Maker MV and RPG Maker MZ).

The game folder has no readable data files

RGSS archives (.rgss3a and friends) and Enigma Virtual Box packed executables are decrypted and unpacked automatically during project creation. See Encrypted & Packed Games.

Can I translate the Linux version of an MV/MZ game?

Yes. Linux ports keep the same data and js folders as the Windows release, so both the Windows and the Linux edition of SLR Translator parse them: select the port's nw / Game binary or its start.sh launcher instead of Game.exe in the project wizard. Export or inject works the same way.

A script bit keeps getting broken during translation

That is the Aggressive Splitting patterns deciding where text may be split — add an entry for the fragment so it is never cut mid-code. See Custom Parsers & Model Creator; the background on what the codes are is in Escape & Text Codes.

Names and terms are translated inconsistently

Run the glossary extractor before batch translating: it collects recurring names and terms so you can fix one translation per term, which the batch then applies everywhere. See Glossary Extractor.

Tips

Regex is your friend

Regular expressions look intimidating but save hours of tedious fixes — mass-rename terms, strip artifacts, or filter rows by pattern. See Find & Replace.

Use the context translation for tricky lines

For lines whose meaning depends on surrounding dialogue, translate the selection with context so the model sees the neighboring rows. See Context Translation.

Check the spell checker before exporting

The offline English spell checker sweeps the translation columns and catches the typos bulk editing introduces. See Spell Checking.

Housekeeping

Does SLR Translator need an internet connection?

The editor, parsing, OCR, spell checking and documentation are fully offline. Only the translation engine talks to the network, and with a local engine server even that stays on your machine. See Overview & Requirements.

Where are my project, backups and logs stored?

The project is a single .slrproj file you choose when saving; its automatic backups (.1.bak, .2.bak…) sit next to it. Logs go to data/logs/, and the working copy of game data lives in the staging directory — all locations are covered in General Settings.

Where are the app settings stored?

Everything lives inside the app folder, so SLR Translator stays fully portable: your preferences are saved to data/config.json, and the browser profile that holds the remaining UI state (spell-check dictionaries, caches, crash reports) is kept in data/profile/. The app never writes to ~/.config (Linux).

One small inert exception exists on Windows: the browser engine's built-in crash reporter is hard-wired to %LOCALAPPDATA%<app name>\User Data and offers no setting to relocate it. That folder only stores crash diagnostics (about 1 MB, written on a crash) — never settings, projects or translations — and can be deleted safely whenever the app is closed.

Because the profile is per-installation, copying the app folder to another machine or user account carries the settings with it; deleting the folder leaves nothing behind. Note that launching the executable from a different working directory is not supported: the relative data/ paths are resolved from the app folder, so always start it in place (double-clicking the executable, or SLR Translator.sh on Linux).

How do I get help, or report a problem?

Press F1 — the full documentation is bundled and searchable offline. If something is actually broken, report it (with the log file — see General Settings for where logs live); problems that are never reported are problems that never get fixed.
