Automatic Word Wrapping

Japanese message windows are sized for Japanese text: RPG Maker MV's default message window fits about 28 full-width characters per line, and 24 when a face picture is shown. English translations are set in proportional fonts where the same number of characters takes far more room — unwrapped translated lines overflow the window, run off the screen or collide with the next line. Automatic Word Wrapping re-breaks the translated lines so they fit the window.

The alternative — shipping a more condensed font and/or a smaller font size — is covered on the engine pages: RPG Maker MV fonts and RPG Maker MZ fonts. The two approaches work together: wrapping fixes the message windows, a condensed font helps where wrapping cannot (menu text may still escape the screen — but wrapped is always better than unwrapped).

The toolbar button

Automatic Word Wrapping runs from the labelled Word Wrap button in the main toolbar's translation group (after Start Translation). Its tooltip states the contract:

Automatic Word Wrapping (Only works with English in column 1 and 2, and will replace column 3.)

That means: the source text must already be English (a Japanese original is not translated or wrapped), and the tool writes its result into Wrapped translations [3], replacing whatever that column held. Run it after translating, before exporting.

The wrap prompt

Clicking the button asks: Please enter the maximum monospace character amount per line. -4 for Avatar picture contexts. Accepting the default produces a best-effort wrap at the configured lengths (24/20 with the default options); the default value itself can be changed in the options. Everything the prompt accepts:

InputEffect
a numberWrap to that many monospace characters per line. Contexts with a face picture get 4 characters less (the -4 for Avatar picture contexts note) when the value is above 5.
the defaultBest-effort wrap using the Short Length / Long Length option values — 24/20 characters with the defaults. Recommended when no font changes are planned outside the tool.
stintBest-effort wrap for the Stint Ultra Condensed font: 52/46 characters.

pstint / psizeThe same two profiles with a p prefix, for unusually small dialogue boxes the picture context does not mark: 46/46 and 36/36 characters.

nukeEmpties the cells of all translation columns in all rows. Caution: this cannot be undone.
cwrapableCopies Original Text [0] into Initial Translations [1] for rows with wrappable contexts — useful when the source text is already English and only needs wrapping. Rows with anything in columns 1–4 are skipped.
ceverythingThe same copy for all rows regardless of context (same skip rule: columns 1–4 filled are left alone).
ignoreallerrorsClears the Errors [4] cells so previously error-flagged rows are wrapped again on the next run.

Which columns are read and written

  • Read: the English is taken from Translation Corrections [2], falling back to Initial Translations [1] when column 2 is empty.
  • Written: the wrapped result goes into Wrapped translations [3], replacing its previous content. Columns 1 and 2 are left untouched.
  • Skipped: rows without context information, and rows carrying an entry in Errors [4] — a flagged translation is never wrapped over.

The column choice is what makes wrapping safe: the export rule ships the rightmost non-empty cell of a row (see Editor Basics), so the wrapped text in column 3 automatically outranks the raw translation in columns 1 and 2. An entry in Errors [4] or Overwrite [5] still wins over column 3 — Overwrite [5] is never modified by wrapping and keeps the final say at export.

How width is measured

The wrap does not blindly count characters. Text is rendered off-screen in a hidden 24 px element set to the Font Family option's font (default mplus-1m-regular), and lines are broken by measured pixel width. Lengths are expressed in full-width (monospace Japanese) character units because proportional fonts change width per character: with the defaults, 28 such characters fit a default MV message window line without a picture, 24 with one — the option defaults (24/20) wrap a little tighter than that.

Set Font Family to a font that looks as similar as possible to the game's actual text font. If the measuring font is wider or narrower than the game's, the wrapped lines will not match what the game renders.

Two other wrapping mechanisms

Automatic Word Wrapping is one of three wrapping features in the tool — they are separate mechanisms and are configured separately:

  • Automatic Word Wrapping (this page) — the toolbar button. Runs over the whole project on demand, writes Wrapped translations [3], measures widths in pixels with the SLR Batch options above. The recommended default after a batch translation.
  • Word Wrap By Tag — rules of a color tag plus a maximum line length, set in the export options dialog (see Exporting the translation). They are applied at export time to rows carrying the matching tag, regardless of column 3 — useful to wrap exactly the tag groups you choose as the files leave the tool.
  • Wrap texts (legacy) — a Wrap texts entry in the Objects panel context menu opens the old Wrap text dialog and wraps the selected files per-file with its own settings. It predates the automatic button; prefer the button unless you need its per-file behavior.
