Automation Editor

The Automation Editor is the Script Editor window in automation mode: you write the body of a JavaScript function once, and SLR Translator executes it for every file, row or cell of the open project — batch-processing work that would be unbearably repetitive by hand. Scripts are plain .js files stored on disk, so they can be reused across projects and shared.

Opening it

There is one entry point per workspace — the editor opens preconfigured for it:

WhereWorkspaceYour code runs…
More Tools menu → Execute Global Script global once, with no iteration object.
File list context menu → Create Automation → For each object objectIterator once per file (checked files, or all files when none are checked).
File list context menu → Create Automation → For each row rowIterator once per row of every visited file.
Grid context menu → Create Automation gridSelection once per cell in the selected range.
Find window: context menu on the search results foundCells once per found cell you selected in the results.

The editor window title and footer always show the active workspace, so you can tell which iteration model you are editing for.

The iteration object

Your code is the body of an async function invoked once per item, with this bound to the current item. Everything below is also listed by the built-in this reference popup (click the highlighted this under the editor):

MemberMeaning
this.fileId of the file being visited.
this.index / this.maxIndex / this.isLastProgress through the run; isLast is true during the final iteration.
this.rowIdRow number within the file.
this.keyTextThe original text of the current row (the key column).
this.cellsThe row's cells as a mutable array — writing to it edits the grid (column 0 is the key column, the first translation column is 1).
this.tagsThe row's color tags as a mutable array.
this.parameters / this.context / this.commentsThe row's parameters, context entries and cell comments.
this.text, this.colId, this.cellCoords, this.setText(text)Cell workspaces only: the visited cell's text and coordinates; setText writes the visited cell (never the key column).
this.getBestTranslation() / this.getBestTranslationCol()Row workspace only: the text (or column index) of the rightmost filled translation — the value export uses.
this.userInputValues from the script's input form, if it defines one.

Two helpers exist outside this: session, an object that starts empty on every run but survives across iterations (use it to keep counters or caches), and die(message), which halts the whole run immediately. The full application API — the project, the UI layer, common helpers, require — is in scope as well.

Running

  • Run with the Run button or F10. A confirmation offers to save the project first — recommended, since automations edit the grid directly.
  • A loading overlay with a Stop Process button appears; stopping takes effect after the current iteration. die() stops immediately.
  • All cell edits made through this.cells or setText() are recorded; when the run ends the grid refreshes and translation progress is recalculated automatically.
  • Script output and errors are printed to the developer console (the bug button opens DevTools on SDK builds).

Saving and quick launch

  • Scripts are saved as .js files under data/custom-scripts/<workspace>/ inside the application folder — one folder per workspace. New, Open, Save, Save As and the file list next to the path field all operate there; the last opened file per workspace is reopened automatically.
  • The star button (Create shortcut of the current script) publishes the saved script to that workspace's Run Automation menu: the file list context menu for For each object/row, the grid context menu for cell scripts, and the Find results context menu for found-cell scripts. Invoking a published script asks for confirmation, then runs it without opening the editor.

Input forms

The Form Builder button opens a visual form designer. The designed form is embedded into the script as a special comment, and when the script is executed the form is shown first — its values arrive in this.userInput. Canceling the form cancels the run. Use this to parameterize reusable scripts (a toggle, a number, a choice of column) without editing code.

Examples

A row-iterator script that fills the first translation column with the original text whenever the row has no translation yet:

if (!this.getBestTranslation()) {
	this.cells[1] = this.keyText;
}

Stopping a long run from within the script:

if (this.index > 200) die("Processed enough rows for now");
