Glossary Extractor

The glossary extractor builds a list of the proper nouns in a project — character names, places, organizations, skills, items — with translations and notes, and feeds that list to the DSLR engine during translation so names stay consistent across thousands of lines. It is a DSLR feature: it uses the DSLR glossary endpoint settings and only DSLR injects the result into its prompts.

It is started from the Glossary button in the main toolbar's translation group (the button before Start Translation). If a glossary already exists in the session, the same button opens it in the editor instead of starting over.

The glossary is an optional quality step: it costs extra tokens and is worth it mainly on a capable model. If you use it, generate it before batch translating. The DSLR option Auto-Inject Glossary (on by default) "automatically appends the generated glossary to the system prompt during translation. Generate a glossary first using the 'Glossary' button in the toolbar." — a glossary created after the run has nothing to stabilize. See Batch Translation for the recommended order.

How extraction works

Generation runs in three phases:

  1. Local extraction. The whole project is scanned with language-specific patterns: nameplate codes (\N[1] style placeholders and \n<Name> nameplates), katakana words (a built-in list filters common UI loanwords), and names quoted in Japanese brackets. Everything found at least twice becomes a candidate; frequent character IDs are collected separately.
  2. LLM extraction. The source text is split into chunks and each chunk is sent to the LLM with the glossary extraction prompts. The LLM returns new terms as JSON, must ignore generic words and template strings, guesses genders for character placeholders from speech patterns, and sees the already-collected terms so it does not re-extract them. Which endpoint is used is all-or-nothing and driven by Glossary API URL: while it is blank, the main translation endpoint (Endpoint 1) is used with all of its options; once a glossary URL is set, ONLY the glossary endpoint, key, model and sampling options are used (a blank glossary field is sent as blank, never copied from the main endpoint).
  3. Merging. Local and LLM results are merged, role/profile information from the game's actor data is attached to character entries, and the editor opens.

The glossary editor

The editor is a table with one row per term:

ColumnMeaning
OriginalThe Japanese term. Clear this field to delete the term on save.
TranslationThe English rendering to use consistently.
TypeCategory such as female character, male character, monster, location, organization, skill, item — or your own types via Glossary Custom Types.
SourceWhere the term came from (local scan, LLM, manual, imported) and how often it was seen.
Role / ProfileFree-text role description the LLM sees — for example a character's occupation or relationships.
NoteFree-text notes, also sent to the LLM.

Once a term has a translation, translations are checked against it: if a source line contains the term but the English drops or renames it (for example Aida rendered as Ada), the line is rejected and retried with the missing terms listed. Character and name entries also accept a matching pronoun or gendered word, and any term can be authorized with a different rendering by appending GLOSSARYDIFF at the end of the response. Matching is stem-based, so an inflected form of the term (brainwashed for Brainwashing, transformed for Transformation) still counts. This runs with no model call, so it works even when Review (QC/judge) is off; entries typed unknown and entries without a translation are never enforced. See Reject Missing Glossary Terms for the details.

A glossary translation must be a single usable rendering, so auto-extraction drops any term whose English offers alternatives (Charm/talisman, Charm or talisman), contains parentheses or leftover Japanese, or reads as a definition. The extraction prompt asks for one universally-usable rendering and the term is discarded if the model still returns alternatives, since an ambiguous entry would only make the consistency check reject correct translations. When extraction finishes, the editor opens with a reminder to skim the generated terms and delete any that still look wrong before saving.

Buttons along the bottom:

  • Save Glossary applies your edits and activates the glossary; Cancel keeps the unedited version.
  • + Add Term adds a manual row.
  • Export / Import write and read the glossary as a JSON file — including a merge-or-replace choice on import.
  • Generate New discards everything and extracts from scratch; Build From Existing re-runs extraction using the current terms as the base; Resume Generation continues a paused run from the last finished chunk.
The glossary lives in the session only — nothing is written to disk unless you export it. Export the JSON to keep a project's glossary across sessions, then import it the next time.

Pause and resume

  • During generation the progress overlay offers Pause and Abort. Progress is checkpointed after every chunk, so pausing (or a provider error such as an expired key) loses nothing: a Resume Generation button continues from the exact chunk where it stopped, and a paused run opens the editor with the partial results.
  • Chunk size, line deduplication, code-stripping before dedup and which tag groups feed extraction are configurable in the DSLR options (Glossary Chunk Size, Glossary Deduplicate Lines, Glossary Strip Codes for Dedup, Glossary Include Dialogue Tags / Glossary Include Script Tags — rows with always-excluded tags such as red or blue are never sent).
  • Japanese-specific local patterns can be disabled with Disable Japanese Extraction for non-Japanese projects.

How it is applied

  • Auto-Inject Glossary (default on) appends the glossary to the DSLR system prompt during every translation — manual Ctrl+G and batch translation alike.
  • Smart Glossary Filter (default on) sends only the terms that actually appear in the current request, saving tokens on small-context models; disable it to always send the full list.
  • The injected block is built from the Glossary Prompt Format template (the placeholder GLOSSARYTEXT marks where the terms go) and lists terms grouped under type headers as - 'japanese' = 'english' lines with profile and note appended. Terms with no translation, profile or note are omitted.
  • While a glossary is active, the DSLR Clean Cache stops writing (and those entries are not reused) — glossary-dependent translations are project-specific.
  • Glossary extraction uses the main translation endpoint while Glossary API URL is blank, or its own glossary endpoint, sampling, retry-delay, custom headers/parameters and reasoning options once a glossary URL is set. The global Repetition Loop Threshold options apply to glossary streaming too — for glossary responses the entries tier counts repeated term definitions, which can never legitimately repeat (see DSLR Translator).

Related options

Everything glossary-related is configured in Options → Translator & Language → DSLR (recommended): endpoint and model, temperature, JSON schema / json_object response modes in the Glossary groups of the Connection & Model and Sampling & Generation sections; max tokens, the absolute token cap and the context length limit in Batching & Limits; chunk filter behavior in the Glossary Extraction section; and the extraction prompts themselves in Prompts. See DSLR Translator for the shared endpoint concepts.
