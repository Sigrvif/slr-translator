Japanese Locale Configuration

Older RPG Maker games (XP, VX, VX Ace) were built for Japanese Windows. Their text files are often not UTF-8, and game folders frequently contain Japanese characters in file and folder names. This page explains what that means for translation and what SLR Translator does about it.

Why locale and encoding matter

Two separate problems are traditionally associated with translating Japanese games on a non-Japanese system:

  • Character encoding: game data and scripts may be stored in a legacy Japanese encoding (such as Shift-JIS) instead of UTF-8. Naively reading such files as UTF-8 turns the text into garbage.
  • Path handling: helper programs launched with a Japanese project path on a non-Japanese locale can receive a mangled path (Japanese characters become ?), because on Windows the arguments of external processes are decoded with the system ANSI code page.

What SLR Translator does automatically

You do not need to change your system locale for SLR Translator itself. The tool handles both problems internally:

  • Encoding detection and conversion: every text file is opened through an encoding detection step (character-set statistics plus the file --mime-encoding utility, with a streaming fallback for non-ASCII paths). The file is decoded with the detected encoding and written back with the same encoding, so Shift-JIS material round-trips correctly.
  • Locale-safe path passing: the Ruby helper that unpacks and repacks RGSS data (used for XP, VX and VX Ace projects) never receives Japanese paths on the command line. Instead, the paths are written to a temporary UTF-8 JSON manifest and passed to the helper by an ASCII-only reference. The helper reads the real paths back from that file, which works on every system locale.
  • Bundled runtimes: the PHP and Ruby helpers the tool relies on ship inside the application package, so their behavior does not depend on your system's language settings.
These mechanisms exist specifically so that Japanese game folders work on English (and other) locales. If a path with Japanese characters is ever rejected, check that the path is intact in your file manager first — SLR Translator will report the path it cannot access.

Do you need to change your system locale?

For translating with SLR Translator: no. Keep your system locale as it is; project creation, parsing, translation and applying the translation are all locale-safe, on Windows and on Linux.

What happens outside the tool is out of its control — a translated copy contains the same files the original game had, so anything the game itself requires to display or run correctly (such as fonts) still applies to the copy.

If text still looks wrong

  • Garbled text inside the grid is almost always an encoding problem in the source file. Re-check the game files in an editor that can switch encodings; the tool detects encodings, it does not guess impossible ones.
  • Garbled file or folder names point at a path problem, not an encoding of the content. Verify the folder name in your file manager before creating the project.
