Error Codes

After translating a cell, SLR Translator compares the translation against the original text and checks that everything the game needs to parse — text codes, placeholders, quotes, brackets — survived the translation. When something looks broken, it writes a marker into the row's Errors [4] column (see Editor Basics). The markers all start with SHISAYE., the author's handle.

When a check fires, the affected text is usually marked inline at the exact problem spot: the first error found is stored verbatim with its surrounding text so you can see where the issue is, and any further codes for the same cell are appended and de-duplicated. After a translation you may see an alert telling you to search for SHISAYE with the Find dialog (Ctrl+F) — that lists every cell carrying an error code (see Find & Replace).

How to read the codes

  • Codes are plain text in the Errors column — click the cell to see them, and use Find with the text target SHISAYE to jump from one to the next.
  • Most codes describe what the checker saw, not why the model produced it: LOSTBACKSLASH5 means an escaped quote appears in the translation but not in the original, whatever the reason.
  • Numbered suffixes (BROKENNAME1…9, LOSTBACKSLASH1…10) distinguish which variant of a problem was detected — for fixing purposes they all mean the same family of breakage.
  • An error code is a warning to check the cell, not a guarantee that the game will crash — but several families (LOSTBACKSLASH, MISSINGPLACEHOLDER, S.NEEDSTOBEBEFORE.D) mark issues that very likely will.

Translation failures

CodeMeaningTypical causeFix
SHISAYE.TRANSLATIONFAIL The engine could not produce a usable translation even after its recovery attempts. The last response (or the original text, if there was none) is written into the cell with this code appended so the batch does not fail completely. Endpoint returned garbage, refused, or timed out on this line; all retries and fallback models were exhausted. Re-translate the cell manually, ideally with another engine or model. Rows containing this code are never stored in the translation cache, so a re-run will try again.
SHISAYE.$1SUGOIERROR A corrupted number of the form 12xF34 was found in the translation — a numeric garble typical of a translator server that crashed mid-generation. The translation server lost chunks of its output. Re-translate the cell; if it repeats, restart or lower the load on the server (see Batch Translation).
SHISAYE.WRONGAIRESPONSE The model answered with chat instead of a translation — the preamble “Let me translate those Japanese phrases to English for you:” was detected in the output. Prompt/template mismatch, or a model that ignores the translation template. Re-translate the cell; if it repeats, check the engine's prompts and template settings (see DSLR Translator).
SHISAYE.POTENTIALESCAPERCRASH The output contains the repeated apology “I'm sorry. I'm sorry.” — the model refused or looped instead of translating. The model balked at the content or hit a repetition loop. Translate the cell manually, or with a different model.

Missing, extra and unknown commands

CodeMeaningTypical causeFix
SHISAYE.MISSINGCOMMAND A \command[…] present in the original is gone from the translation. The model dropped or mangled a control code. Restore the command from the original cell (see Escape & Text Codes).
SHISAYE.MISSINGCOMMAND.B A bracket command without a leading backslash ([…]) present in the original is gone. Plugin/script bracket tokens lost during translation. Restore the token from the original cell.
SHISAYE.MISSINGBRACKET A \command[…] lost its bracket part — the command name may remain, but the […] is gone. The model treated the bracket as removable punctuation. Restore the full command including its brackets.
SHISAYE.MISSINGBOUNDARY A \command<…> lost its <…> part. Angle-bracket arguments stripped by the model. Restore the full command.
SHISAYE.ADDITIONALCOMMAND The translation contains a \command[…] that the original does not have. The model invented a code, or restored a placeholder wrongly. Remove the invented command.
SHISAYE.WRONGCOMMAND A bare backslash command appears in the translation that is absent from the original. Same as above, for commands without brackets — often a stray “\” the model added. Remove it, or verify it is a real code the game supports.
SHISAYE.COMMANDGAP A command has junk between the name and the bracket, e.g. \C [1]. The model inserted a space or character inside the code. Close the gap: \C[1].
SHISAYE.UNKNOWNCOMMAND1 A bracket token ([…]) that is not a known command still contains Japanese in the translation (only checked when the target language is English). Part of a plugin command was treated as translatable text. Check the original; restore the token or translate it deliberately if it really is text.
SHISAYE.UNKNOWNCOMMAND2 Same as above for angle-bracket tokens (<…>) containing Japanese. Plugin argument translated by mistake. Restore from the original.
SHISAYE.UNKNOWNCOMMAND3 A doubled backslash before a bracket number, e.g. \\[1]. The model (or a recovery step) escaped a backslash that should be single. Fix to a single backslash if the original had one.
SHISAYE.UNKNOWNCOMMAND4 A forward-slash command such as /c[1] — the slash direction got flipped. Model typo or overzealous escaping. Restore the backslash form from the original.

Malformed commands

CodeMeaningTypical causeFix
SHISAYE.BROKENNAME1–9 A name command (\n[…], \N[…], \nw[…], \NW[…], \name[…]) has junk where its [ or < should be — e.g. \n=[1]. The nine variants cover upper/lowercase and the < form. The model altered the character right after the command name. Restore the exact command syntax from the original.
SHISAYE.BROKENVARIABLE1 / 2 A variable command \V(1) / \v(1) uses parentheses instead of brackets. The model swapped bracket styles. Fix to \V[1].
SHISAYE.MISSINGVARIABLEB1–3, SHISAYE.MISSINGVARIABLE.B1–3 A \B[…] / \b[…] command is broken: followed by junk instead of [ (1), cut off at the end of the text (2), or followed by digits without brackets (3). Truncated or half-restored command. Restore the complete \B[n] form.
SHISAYE.BROKENCOLOR A color command \C[…] whose bracket does not start with a digit, e.g. \C[one]. The model spelled out the color index. Restore the numeric form \C[n].
SHISAYE.BROKENDOLLAR An escaped dollar \$ appears in the translation but not the original. Backslash wrongly attached to a normal dollar sign. Remove the backslash unless the original had \$.
SHISAYE.BROKENCOMMAND A backslash command followed by a stray -, | or ', not present in the original. Model garbled a code into a hyphenated word. Compare with the original and restore.

Stray backslashes

CodeMeaningTypical causeFix
SHISAYE.LOSTBACKSLASH1 / 2 A dangling backslash at the end of the text or before a space — variant 1 for a single backslash, variant 2 for a doubled one. A stray backslash can crash the game's text parser. The model dropped the character that followed the backslash. Restore the full code from the original, or delete the stray backslash.
SHISAYE.LOSTBACKSLASH10 A backslash directly before an opening parenthesis \( (also flagged as LOSTBACKSLASH2 by a second check), or a backslash glued to one of the error markers themselves. Model inserted parentheses around a code, or a repair step half-fixed a previous error. Remove the parenthesis or restore the intended code.
SHISAYE.LOSTBACKSLASH4 / 8 A backslash before a Japanese quote mark: \「 or \」. The model escaped a bracket quote that was plain text in the original. Remove the backslash if the original quote was unescaped.
SHISAYE.LOSTBACKSLASH5 An escaped quote \" or \' appears in the translation but not in the original. Escaping added where the game does not expect it. Match the original's quoting.
SHISAYE.LOSTBACKSLASH7 The sequence \n\ (a line break followed by a dangling backslash-space). Truncated code after a line break. Restore the complete code.
SHISAYE.LOSTBACKSLASH9.STAR An escaped asterisk \* in the translation. Backslash attached to a normal asterisk. Remove the backslash unless the original had \*.
SHISAYE.ESCAPEDBACKSLASH A doubled backslash before a letter (\\n, \\C…) appears although the original has none. The model (or a template) escaped the escape character. Reduce to the single-backslash form the original uses.

Bracket and quote mismatches

CodeMeaningTypical causeFix
SHISAYE.WRONGBRACKET1.DOT / 2.DOT A bracket command ends with .] instead of ] — e.g. \V[1.] (2) or text ending in .] without any opening bracket (1). The model treated the closing bracket as sentence punctuation. Match the original's bracket style.
SHISAYE.WRONGBRACKET3 / 4 A command closes with 」] or ]」 — a Japanese quote and bracket swapped or doubled at the start of the text. Quote/bracket confusion in scripts. Restore the original arrangement.
SHISAYE.LOSTSTAR1 The text begins with content followed by *] but has no matching [ — e.g. something*]. Half of a bracket token was lost. Restore the opening part of the token.
SHISAYE.INNERBOUNDARY The translation is wrapped in quotes but contains an extra quote inside, while the original had none — three quotes where there should be two. The model added quotation marks around a quoted string's content. Remove the inner quote; unbalanced quotes are a high crash risk.
SHISAYE.MISSINGQUOTES / MISSINGQUOTES2 On rows whose original is a quoted code string (green-tagged), the outer double (or single) quotes were lost. The model stripped the quotes around a script string. Re-wrap the translation in the original quotes.
SHISAYE.3INNERQUOTES, 5INNERQUOTES, 7INNERQUOTE, 9INNERQUOTE (and the 2 single-quote variants) On quoted code strings, the number of inner quotes in the translation does not match the original — the number is the expected quote count. The 2-suffixed variants are for single-quoted strings. Quotes merged, split or added by the model. Match the original's quote count.

Placeholder problems

CodeMeaningTypical causeFix
SHISAYE.MISSINGPLACEHOLDER1–5 Format placeholders (%s, %d, and @/# tokens) from the original are missing from the translation. The number is how many placeholders the original had (checked from five down to one). The model dropped the format tokens — in RGSS scripts these are filled in at runtime, and a missing one will crash the game. Restore every placeholder from the original, keeping their order.
SHISAYE.S.NEEDSTOBEBEFORE.D / D.NEEDSTOBEBEFORE.S The order of %s and %d differs from the original. The model reordered the tokens — the game fills them in the original order, so swapped tokens put the wrong value in the wrong slot and usually crash. Restore the original order.
SHISAYE.LOSTPLACEHOLDERMVMZ A percent placeholder (%1, %2…) appears in the translation but not in the original. The model inserted a placeholder that the game will not substitute. Remove it.
SHISAYE.PLACEHOLDERGAPMVMZ A percent placeholder is corrupted with extra characters between % and the digit, e.g. % 1. The model spaced out the token. Fix to %1.
SHISAYE.LOSTPLACEHOLDERMIDDLE A protected placeholder was missing from the translation; the engine re-inserted it at its best-guess position in the sentence and marked the cell so you can verify the placement. The model dropped the token; automatic recovery put it back. Check that the re-inserted placeholder sits where it reads correctly.

Script structure

CodeMeaningTypical causeFix
SHISAYE.TOOMANYCOMMAS / TOOFEWCOMMAS On LL_GalgeChoiceWindowMV setChoices script rows, the translation has a different number of commas than the original. These scripts use commas as argument dividers. The model added or removed commas while translating the choices. Adjust the comma count to match the original.

Notes

  • The error checks run automatically after every translation — per cell for interactive translations, and as a fix-up pass after each batch. You do not need to trigger them.
  • The purple cell tag is a related but separate signal: it marks rows where the batch translator suspects the whole result is broken (truncated or looped output), before the per-code checks run. The mediumpurple tag marks the DSLR semantic review's findings instead. See Cell Color Tags.
  • Repetition loops that happen while a response streams are usually caught before they ever reach the output: the DSLR repetition loop guard terminates the looping response early and retries it with an increased repetition penalty (logged as “repetition loop detected …”, distinct from a “length” finish reason). Output that is still looped either survived those retries or ran with the guard's thresholds set to 0 — see DSLR Translator.
  • Codes whose fix mentions “restore from the original”: the original text is always the leftmost column (Original Text [0]) of the same row.
